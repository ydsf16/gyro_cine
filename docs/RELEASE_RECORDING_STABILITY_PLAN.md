# GyroCine 发版录制稳定性复测计划

本计划用于每次 TestFlight / App Store 候选版本。测试对象是**实际安装的候选构建**，结果以设备生成的 MOV 和日志为准。模拟器、编译通过、XCTest 按钮点击成功均不能替代录像验收。

## 1. 本轮环境与记录

| 项目 | 本轮待填写 |
| --- | --- |
| Git commit / 分支 / 是否有未提交改动 | |
| App 版本与构建号 / Debug 或 Release | |
| Xcode / iOS / 设备型号与系统可用空间 | |
| SSD 名称、容量、文件系统、剩余空间、连接方式 | |
| Mac 到 iPhone 的连接 | Wi-Fi；每阶段记录 `devicectl` 的 `Transport Type: localNetwork` |
| SSD 测速 | 用户估计约 380 MB/s；另记 App 实测平均、后半段最低、最长写入停顿 |
| 环境 | 充电状态、起始/结束 thermalState、室温可得时记录 |
| 运行 ID / 证据目录 | `YYYYMMDD-HHMM-<build>-<device>`；独立目录保存日志、截图和结果表 |

测试前先检查 `git status`、相机权限、麦克风权限、SSD 授权、剩余空间及 App 是否识别目标盘。记录当前用户配置，测试完成后恢复。不得卸载 App、抹盘或批量清理用户素材。只删除本轮有明确 ID 的测试文件，并先保存异常原片与诊断数据。

### 无线控制闸门

无 SSD 的内部/专用存储与界面回归可改用 USB；记录实际 `wired` 传输。无线 XCTest 握手失败时优先完成 USB 阶段，不把驱动失败计为 App 功能失败。

1. USB 从手机断开，SSD 接手机。`xcrun devicectl device info details --device <UDID>` 确认 `localNetwork`。
2. `devicectl device capture screenshot` 截取一张预检图；运行一项短的真机 UITest，确认能读取界面、点击和取得 XCTest 附件。
3. 若 XCTest 连接断开，记录为**测试传输故障**。核查 `docs/XCTEST_CONNECTION_2026-10-17.md`，恢复连接后重做被中断的测试；不能把 runner code 74 计为录像失败或通过。
4. 长录主要由 App 自行持续录制。测试控制端断线后，先确认手机录制状态和结果文件，再决定是否重试，避免重复开启录制。

## 2. 判定原则与证据

每个用例保留：起止时间、截图、实际镜头/编码/尺寸/FPS/存储、SSD 测速结果、开始与停止响应、最终文件路径与字节数、App 事件/错误日志、MOV 检查结果。选择不支持的配置记为 **N/A（设备未提供）**；启动前拒绝、录制中断、保存失败分别记为不同失败阶段。

**录制通过**须同时满足：

- 录制能开始、停止和完成保存；没有卡在 Finalizing，随后无需重启即可再次录制。
- MOV 可读取并完整解码；尺寸、编码、时长和实际平均帧率与所选规格相符。检查逐帧 PTS 单调、无重复，统计最长间隔、超过 `1.5 / fps` 的间隔和估计缺帧数；目标为录制区间 **0 个估计缺帧**。若出现缺帧，保留原片并定位时间段、热状态、写入停顿、缓冲峰值和系统压力，不用“能播放”代替通过。
- 有音频轨且抽听可用；对于提供真实逐帧 K、宣称 Gyroflow 兼容的格式，有内嵌 IMU 及与视频区间匹配的 K。Media 中显示绿色 IMU；仅显示标记不足以验收，应读取实际轨和样本。若设备格式不提供 K，记录视频/音频结果及明确的 `!IMU` 提示，将 Gyroflow 兼容项判为 N/A，不能写成完整通过。
- 竖拍/横拍分别检查显示方向、MOV 旋转信息及 Gyroflow 预览与导出方向。抽取至少一段导入 Gyroflow，确认运动数据和镜头参数被识别，并完成短片增稳导出。
- SSD 录制最终文件在系统 `DCIM/100APPLE/IMG_####.mov`。内部与专用存储按各自 `Media/Log` 路径核查。不得为验收重编码或移动 SSD 原片。

**保护行为通过**须满足：容量/写入异常在继续损坏文件前停录并给出明确状态；原片及恢复资料保留；重新接入 SSD 后可重新录制。受控断盘片段可以是不完整文件，须明确标记，不能计作正常录制通过。

MOV 层面使用 `ffprobe`、`tools/analyze_capture_cadence.py` 和 `tools/validate_recording.py`（按各工具当前参数）；RAW 长片优先在设备端完成全帧解码与轨道验证，仅传回小型统计和日志。需要桌面兼容验收时选取原片单独复制，不通过 Wi-Fi 批量传输数十 GB 长片。测试报告记录命令、工具版本和原始 JSON，不能只写“正常”。

## 3. 执行顺序

### A. SSD 与基础冒烟

| ID | 操作 | 验收重点 |
| --- | --- | --- |
| A01 | App 冷启动、前后台切换、关闭重开；截图 | 预览、相机/IMU/SSD 状态、已保存配置，无启动卡死或重复旧错误 |
| A02 | 选择外部 SSD、目标盘、运行 App 内 8 GiB 测速 | 记录平均、后半段最低和最长停顿；检查临时文件清理；按当前配置读取建议速度（含 30% 余量） |
| A03 | H.265 4K60：内部文件与 SSD 各录约 15 秒 | 基础音视频/IMU/K、存储路径、Media 可见性、保存后再次录制 |
| A04 | 专用视频存储 RAW 4K30 短录（容量已分配时） | 与 SSD 路径独立回归；未分配则记录阻塞及设置入口 |

**380 MB/s 是当前用户估计值，不作为保证速度。** 若实测持续速度低于规格建议值、最长停顿超过该 RAW 帧率的 10 帧缓冲预算，或预计空间不足，先记录为高风险。高风险规格仍可做**受控短录**观察丢帧/报错，不直接安排五分钟长录。不得靠扩大缓冲掩盖持续写入不足。

### B. RAW 规格矩阵：1× 物理镜头

只运行设备当前显示可选的组合。RAW = ProRes RAW，HQ = ProRes RAW HQ。

| 编码 | 分辨率 | 帧率 | 第一轮 | 下一步 |
| --- | --- | --- | --- | --- |
| RAW / HQ | 4K 4224×2240 | 30 / 60 | 每项 15 秒 | 无异常且速度/容量足够时延至 60 秒 |
| RAW / HQ | Open Gate 4224×3024 | 30 / 60 | 每项 15 秒 | 无异常且速度/容量足够时延至 60 秒 |
| RAW / HQ | 4K / Open Gate | 当前设备实际提供的 120 | 每项最多先 10–15 秒 | 不支持记 N/A；失败记录发生在格式配置、开录、写入还是封装阶段 |
| H.265 / H.265 HQ | 4K、1080p 中设备支持的最高常用帧率 | 60；有 120 则另测 | 各 15 秒 | 对照 RAW 的系统负载和时间轴；240fps 已禁用，不列为可选配置 |

对 29.97/59.94 与 30/60 并存的配置，补一组短录，核对界面选择值和 MOV 实际时间轴。每轮记录 SSD 写入估计速率、缓冲峰值、帧回调迟到、Writer 错误和热状态。若一项出现明显连续缺帧或存储错误，保存证据，先停止该规格后续长录。

### C. 镜头、方向及长录

| ID | 操作 | 验收重点 |
| --- | --- | --- |
| C01 | 0.5×、1×、4× 各选一个最高可用 RAW 规格，15 秒；再做 4×→1×、1×→0.5× | 实际镜头、自动对焦、白平衡、格式最近合法回退、手动曝光设置保留/合法钳制；切镜头后还能录 |
| C02 | 竖拍与横拍各 15 秒；录前及录中改变姿态 | 文件方向、屏幕辅助线、Gyroflow 预览和导出 |
| C03 | 选一项 SSD 稳定可承受的 RAW/HQ 高带宽组合录 5 分钟 | 完整帧时间、热状态、写入停顿、保存/IMU 封装耗时、连续再录 |
| C04 | 再选另一镜头或 Open Gate 的代表组合录 5 分钟；H.265 4K60 另录 5 分钟 | 比较镜头、编码路径；同样做全片核验 |
| C05 | SSD 正常录制结束后受控拔出、插回；另做一次**短录中**拔盘 | 明确中断提示、原片/日志保留、盘恢复后无需重启再录；需用户现场配合 |

五分钟测试前重新核算剩余空间：保留 App 的动态保护阈值与额外安全余量，并按当前配置的实测字节增长估算整段大小。若设备报告热压力严重、空间逼近阈值或已持续丢帧，停止该轮并记录已生成片段；不要为了凑满时长继续消耗存储。C05 留到正常录制矩阵完成后执行。

## 4. 设置与功能开关回归

以下优先使用 `UITests/IMURecordingUITests.swift` 中已有用例，并补真机截图/实际录制核对。UITest 中仍有中文文案选择器；英文系统运行时先改用稳定 accessibility identifier 或中英兼容断言，避免语言导致假失败。

| 组 | 操作与预期 |
| --- | --- |
| 视频设置 | Codec、分辨率、FPS 在同页选择；选项只显示当前物理镜头实际支持值；切换顺序和最近有效配置正确；录制中禁改；重启后保持选择。参照 `testNativeSettingsMenusFullRow`、`testVideoSettingsAndRecordingLocks`。 |
| 存储与输出 | 内部、专用存储、SSD 切换；盘缺失/授权/空间不足有明确提示；SSD 重连、速度测试、Gyroflow/GyroflowNightly 输出选项、BMC/简洁命名；重启保持。检查原片文件名、路径和 Media 能看到 SSD 素材。 |
| 快门/曝光 | A-Max/A/M、速度/角度、180° 随 FPS、ISO/快门手动档位与设备范围、EV、最大曝光；切镜头/FPS 后保留或合法钳制。参照 `testControlsAngleEVAndHaptics`、`testControlsManualSurvivesLensAndFPS`。 |
| 白平衡/对焦 | H.265 的 AL/A/M 与六个预设；RAW 锁定状态；AF-C/MF/LOCK、点击对焦、长按锁定、镜头切回后的连续 AF。录制前后观察实际数值和画面，不仅核对按钮文字。 |
| LUT/取景 | LUT Off、Rec.709 和各内置 Look；预览开关不改变 MOV 像素/编码链路。九宫格、重力水平线开关与横竖旋转；刻度震动反馈开关。参照 `testLUTCarousel`、`testViewfinderGuides`。 |
| 录制交互 | 屏幕 REC、实体音量键启停；待保存时防重复录制；后台/锁屏后的保存或补写状态、错误可恢复。蓝牙遥控另记硬件依赖，不以音量键通过替代。 |
| 素材/场记 | 预览播放无闪烁、缩略图、IMU 标记、分享、保存相册、选择/删除本轮测试文件、SSD 素材显示；场记字段与 BMC 文件名、重启保持。不得在自动测试中删除非本轮素材。 |
| 语言与可访问性 | 系统中文/英文下设置、LUT、Media、提示文字和权限描述；截图检查截断和遮挡。 |

设置项每组至少做“更改 → 生效 → 录制或界面验证 → 退出重开 → 恢复”闭环。测试后恢复原用户配置；若测试修改了默认值，结果中记载最终状态。

## 5. 报告与发版门槛

在 `docs/` 下新建本轮 `RELEASE_RECORDING_STABILITY_<date>.md`，并附一份逐项结果表：`PASS / FAIL / N/A / BLOCKED`、构建、设备、配置、时长、帧数、最大 PTS 间隔、估计缺帧、音频、IMU/K、保存耗时、截图/日志/MOV 路径、问题编号。历史结果不自动继承为新候选版本通过。

发版候选要求：A 项全通过；B 项中**设备宣称支持且测速判断可运行**的组合无未解释失败；C 的代表性五分钟长录及正常停止/再次录制通过；第 4 节核心设置和素材闭环通过。测速判断高风险的规格可以记已知限制，但 App 必须清楚提示并安全退出；严重掉帧、无 IMU 的“成功”片段、卡在保存或无法再次录制均阻止发布。未覆盖的设备/播放器/遥控器明确列为限制，不写成通过。
