## 修改和证据

### 设置菜单

### 提前停止录制

- 剩余空间阈值：`max(5 GB, 估计码率 × 10 秒)`；每约 2 秒检测一次。
- 开录还要求阈值之外至少约 10 秒的预计容量；主存储低于 500 MB 另有保护。
- 达到阈值时停止并提示，保留空间完成音视频及 IMU 封装。
- 不满 1 分钟的剩余时间显示秒数，避免显示“约 0 分钟”。
- 真机测试通过 DEBUG 注入剩余 4.9 GB、阈值 5 GB：自动停止，4.4667 秒、268 帧，全部解码，音频轨和 IMU 存在，封装约 0.084 秒。
- 此为容量读数注入测试，没有真实写满磁盘到 4.9 GB。原先用户看到 0 空间的时刻没有截图证据，不能据事后日志否定该现象。

### 专用存储回收

增加启动、回到前台及删除后触发回收；设置提供“回收可用空间”。系统异步释放块时，部分回收按 2/5/10/20 秒间隔最多重试四次，只在空闲时执行。

启动实测从 144,038,182,912 恢复到 150,000,001,024 字节。删除第一段大文件后第一次只回收到约 62.48 GB，后续释放完成恢复 150 GB；最终 4× 素材删除后也恢复 150,000,001,024 字节。

未卸载 App，以保留用户素材。已验证启动和删除路径，不能声称实际卸载重装已通过。系统回收是尽力恢复，实际物理空间不足时可能低于初始容量。

### 保存及 IMU

测试专用的全视频解码原来同步占用相机队列，现移到 utility 验证队列，保存 UI 无需等待数分钟解码。此阻塞属于 DEBUG 验证路径。

1× 120fps 发现稀疏丢帧形成 125ms 间隔，旧版 >100ms 硬拒绝导致整段 IMU 未嵌入。现按实际 MOV PTS 匹配 IMU，允许稀疏但有效时间轴；仍拒绝非法/重复时间戳及超过约 5% 的大量丢帧，保留 IMU 覆盖及插值间隔校验。缺帧数量留在元数据，新增录制后丢帧提示。原视频的缺帧不会被修复或掩盖。

两个针对性单元测试通过：稀疏 PTS / 大量丢帧，以及重复 / 非法时间戳。最终 Release 的丢帧弹窗已编译，但未通过真机 UI 自动化验收。
